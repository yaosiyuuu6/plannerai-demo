# Agent 运行中消息管理 PRD

## 1. 产品定义

在无外部副作用的 Agent 任务中，让用户在运行期间继续组织消息、及时纠偏，并在暂停后修改最近一次提问，降低因输入错误或理解偏差导致的等待和重跑成本。

- Demo 首页：<https://yaosiyuuu6.github.io/plannerai-demo/>
- 功能入口：打开左侧历史记录中的“规划文档总结”。

## 2. 背景与问题

长耗时 Agent 任务常出现两类问题：

1. 用户发送后才发现错别字或表达错误，希望修改原问题并重新运行。
2. Agent 已经理解偏离，用户希望在本轮运行中立即发送纠偏指令，而不是等待完整结果。

普通聊天的“发送下一条消息”不足以覆盖这两类场景：后续消息需要可管理，纠偏消息需要明确是否已经进入当前运行，历史修改则必须避免产生混乱的对话分支。

## 3. 目标与范围

### 3.1 目标

- 运行期间可继续提交消息，不打断当前任务。
- 待发送消息可排序、编辑、删除或在运行中立即发送。
- 暂停整个对话后，可原位修改最近一条用户消息并重新运行。
- 用户始终能判断消息处于“待发送、运行中发送、已执行”中的哪一状态。

### 3.2 首版范围

- 仅支持无外部副作用的任务，如总结、写作、规划和分析。
- 仅支持修改最近一条已执行的用户消息。
- 修改历史消息后，作废并删除其后的 Agent 内容，从该消息重新运行。
- 不保存可恢复的历史快照，不支持任意历史分支。
- Demo 使用模拟运行日志，不接入真实模型。

## 4. 功能列表

| 模块 | 功能 | 描述 |
| --- | --- | --- |
| 待发送消息 | 普通发送 | Agent 运行中提交的新消息进入输入框上方的待发送区；当前任务不受影响，结束后按列表顺序执行。 |
|  | 拖动排序 | 拖动消息改变后续执行顺序；同时支持 `Option + ↑/↓` 键盘排序。 |
|  | 编辑 | 在待发送区原位修改消息内容；保存前不影响运行中的任务。 |
|  | 删除 | 删除尚未交给 Agent 的消息，删除后不再执行。 |
| 运行中纠偏 | 立即发送 | 点击上箭头后，目标消息立即从待发送区进入当前对话，并标记“运行中发送”。这不是调整下一条顺序。 |
|  | 结束旧过程 | Agent 收到运行中指令后，当前过程立即提前结束，状态显示“已提前结束”，不得显示“已完成”或继续生成旧结果。 |
|  | 撤回 | Agent 接收前显示“取消立即发送”；撤回后消息恢复到原待发送位置。接收后不可撤回。 |
| 对话控制 | 单一主按钮 | 输入框右下角只保留一个状态按钮：有输入时为发送上箭头；运行中无输入时为暂停方块；暂停后无输入时仍为上箭头，点击恢复执行。 |
|  | 暂停整个对话 | 暂停当前运行和后续自动调度；所有待发送消息保留，并可继续排序、编辑和删除。 |
|  | 恢复执行 | 暂停状态下点击上箭头，从待发送列表首条继续执行；队列为空时回到空闲状态。界面不展示“继续”文字按钮。 |
| 修改自己的问题 | 编辑权限 | 运行中不显示历史编辑入口；暂停后，仅最近一条用户消息下方显示铅笔图标。 |
|  | 消息内编辑 | 点击铅笔后，直接在原消息气泡内编辑，右下角提供“取消 / 发送”；不占用底部输入框。 |
|  | 作废并重跑 | 发送修改内容后，删除该消息之后的旧 Agent 内容，并以修改后的消息重新运行；原待发送列表继续保留。 |
| 状态反馈 | 运行状态 | 区分运行中、正在接收运行中指令、已提前结束、已暂停、已完成和空闲。 |
|  | 无障碍与反馈 | 图标操作提供可读名称、悬浮提示和键盘焦点；主要点击区域不小于 44px；排序、删除、撤回等操作提供即时反馈。 |

## 5. 核心交互规则

### 5.1 普通发送与队列

1. Agent 运行中，用户发送消息后，该消息加入待发送列表尾部。
2. 拖动顺序只决定当前任务结束后的执行顺序。
3. 当前任务正常完成后，系统自动取列表首条执行。
4. 对话暂停时，用户新发送的消息只加入列表，不自动恢复任务。

### 5.2 运行中发送

1. 用户点击某条待发送消息的上箭头。
2. 该消息立即出现在对话区，并显示“运行中发送”和撤回入口。
3. 当前 Agent 过程停止扩展并快速结束，标记为“已提前结束”。
4. Agent 接收指令后，撤回入口消失，直接基于该消息开始新的运行段。
5. 未被选中的待发送消息保持原有相对顺序。

### 5.3 暂停与统一主按钮

| 对话状态 | 输入框 | 按钮形态 | 点击结果 |
| --- | --- | --- | --- |
| 运行中 | 空 | 方块 | 暂停整个对话 |
| 运行中 | 有内容 | 上箭头 | 消息加入待发送区 |
| 已暂停 | 空 | 上箭头 | 恢复队列执行 |
| 已暂停 | 有内容 | 上箭头 | 消息加入待发送区，仍保持暂停 |

同一时刻只允许出现一个主按钮，不出现独立的“继续”文字按钮。

### 5.4 修改最近一条消息

1. 用户先暂停整个对话。
2. 系统仅在最近一条用户消息下显示编辑图标。
3. 点击后，消息气泡变成与输入框同风格的白色编辑框，原编辑图标隐藏。
4. 点击取消恢复原消息；点击发送则提交修改。
5. 系统删除该消息之后的旧 Agent 内容，并从修改后的消息重新运行。

## 6. 状态流转

| 当前状态 | 用户操作 | 下一状态 | 结果 |
| --- | --- | --- | --- |
| 运行中 | 普通发送 | 运行中 | 消息加入待发送区 |
| 运行中 | 运行中发送 | 接收纠偏指令 | 旧过程提前结束，执行纠偏消息 |
| 接收纠偏指令 | 撤回 | 运行中 | 消息恢复原队列位置，当前任务继续 |
| 运行中 | 暂停 | 已暂停 | 当前过程停止，队列保留 |
| 已暂停 | 输入消息并发送 | 已暂停 | 消息加入待发送区 |
| 已暂停 | 空输入点击上箭头 | 运行中/空闲 | 有队列则执行队首，无队列则回到空闲 |
| 已暂停 | 编辑最近消息并发送 | 运行中 | 删除旧内容并重新运行 |
| 运行中 | 当前任务完成 | 运行中/空闲 | 有队列则执行队首，否则空闲 |

## 7. 异常与边界

- 运行中发送的接收窗口内只处理一条消息，其他立即发送入口暂时禁用。
- 用户在接收窗口内暂停对话时，运行中发送的消息恢复到原待发送位置。
- 待发送消息内容不能为空；编辑为空时保留编辑态并提示。
- 历史消息编辑仅开放给最近一条用户消息，运行中不展示入口。
- 编辑历史消息期间点击恢复执行，先取消未提交的编辑。
- 正式版本需要持久化队列；Demo 仅保持当前页面生命周期。

## 8. 验收标准

1. 运行中连续发送三条消息，均进入待发送区且不影响当前任务。
2. 拖动待发送消息后，后续执行顺序与列表顺序一致。
3. 待发送消息支持编辑、删除，且不会误改当前任务。
4. 点击上箭头立即发送后，消息进入对话区，旧过程显示“已提前结束”。
5. 运行中发送在 Agent 接收前可撤回，撤回后恢复原队列位置。
6. 运行中发送不改变其他待发送消息的相对顺序。
7. 输入框右下角同一时刻只出现一个主按钮，并按状态执行发送、暂停或恢复。
8. 界面中不出现独立的“继续”文字按钮。
9. 运行中无法编辑已执行消息；暂停后仅最近一条用户消息显示编辑图标。
10. 编辑在原消息气泡内完成；提交后旧回复消失，新运行启动，待发送消息仍保留。

## 9. 成功指标

- 因输入错误追加“更正、不是、重新来”等消息的比例下降。
- 长任务运行期间的消息放弃率下降。
- 运行中发送后，目标指令被正确接收的比例达到 100%。
- 修改最近消息后，旧回复清理和重新运行成功率达到 100%。
- 用户对消息当前状态的误判反馈持续下降。
